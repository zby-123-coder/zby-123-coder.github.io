很多任务一复杂，就被急着拆成“规划 Agent、执行 Agent、审核 Agent”。看上去像组织，实际上常常只是把一个没有想清楚的流程分散到更多 Prompt 里。

我更愿意先问三个问题：

1. 这几个角色掌握的上下文真的不同吗？
2. 它们拥有的权限与可做的动作真的不同吗？
3. 它们被评价为“做得好”的标准真的不同吗？

如果答案都是否定的，先用一个 Agent 加上显式状态、工具边界、Checkpoint 和人工确认，通常更清楚，也更容易恢复。

CRM 的合同拟定、合作状态诊断、督导员之所以可以拆开，是因为它们分别面向内容生成、业务信号判断和动作合规。它们不是轮流说话，而是有不同的输入、输出、权限与责任。

协作的价值从来不在角色名。它在于：复杂度是否被真正隔离，失败是否更容易定位，谁应该停下、谁必须由人拍板，是否终于清楚了。
